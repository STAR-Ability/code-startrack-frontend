# codeStartrack V0.11

## Goal

Incrementally replace the fixed-user V0.1 reader with the documented authenticated, account-scoped V0.11 workspace while preserving Next.js, Nova/Base UI and bilingual presentation.

## Context

The complete repository audit found a working landing page, profile/practice routes, localized UI, Query provider, Zod reader and offline unit/E2E/container checks. The private data flow is limited to two legacy GETs for numeric user 1; login and account management are placeholders. Layout, design tokens, UI primitives, marketing illustrations, localization helpers and testing tools are reusable. Existing route/feature/lib separation supports this extension without rebuilding the project.

Current authority: `prompts/前端api文档.md` and `prompts/前端需要知道的数据库.md`. Older product/API documents describe an earlier stage and are superseded for V0.11. No CodeGraph index exists. Existing user edits and untracked source documents must be preserved.

## Scope

### In Scope

- Complete public DTOs, strict decimal string IDs, envelopes and account ownership checks.
- Session authentication and security flows; multi-account selection and read-only unbound history.
- Dashboard, personal data, six-dimensional profile, windowed analysis/history, recommendation modes/history.
- Job recovery/polling, partial failures, stale/empty/loading/error states and retry cooldowns.
- Static Next.js export, same-origin `/api/v1` reverse proxy and isolated local Demo/fixtures.
- Migration of obsolete contract tests and final contract/isolation audit.

### Out of Scope

- Backend, database, Algorithm or Codeforces API implementation; live backend mutations.
- Judge, editor, real agent, unrelated visual redesign or new general-purpose dependencies.

## Acceptance Criteria

- [x] Runtime API calls use only `/api/v1/**` with session credentials.
- [x] IDs remain strings; account switching/logout/unbinding cannot leak private data.
- [x] All documented student workflows have complete states and bilingual UI.
- [x] Recommendation reads never compute; writes preserve idempotency on retry.
- [x] Sync tasks resume by ID, stop at terminal states and refresh affected data.
- [x] Static build, typecheck, lint, formatting, unit and desktop/mobile E2E checks pass.

## Implementation Stages

### Stage 1 — Contract and infrastructure

Files: `src/lib/api`, root providers, deployment configuration. Replace the old fixed-user gateway with validated V0.11 DTOs and a centralized same-origin client. Establish isolated query keys and static export. Validate schemas, transport and proxy behavior.

### Stage 2 — Identity, accounts and jobs

Files: auth/account components and hooks. Add captcha/email authentication, security settings, selected-account context and async task lifecycle. Validate pagination, role guards, cancellation, unbind and session cleanup.

### Stage 3 — Student workspace

Files: App Router pages, training components, localization. Compose existing primitives for dashboard, personal data, analysis and recommendations; use ECharts for actual analytical plots. Validate nullable data, histories, parameter changes and action states.

### Stage 4 — Audit and verification

Migrate obsolete V0.1 contract expectations rather than retaining forbidden endpoints. Exercise offline synthetic fixtures, delayed account switching and error recovery. Update active contract/deployment documentation, inspect the full diff and run all existing quality gates.

## Testing

- Unit: strict DTOs, unsafe IDs, account ownership, error/transport behavior, idempotency, chart transforms.
- Integration: paginated account discovery, query isolation and job lifecycle.
- E2E: public Demo, authentication, multiple accounts, personal data, analysis, recommendations and errors on desktop/mobile.
- Build/type/lint: all repository quality scripts; container acceptance when Docker is available.

## Risks

The backend implementation has not been verified against V0.11; tests use synthetic contract fixtures. Static export requires moving cookie-derived locale initialization to the client and replacing dynamic server gateways. Old assertions about anonymous live-demo GETs are no longer valid.

## Rollback / Reversibility

Work is isolated on `feature/v0.11-account-workspace` under the normal post-V0.1 workflow. Revert scoped implementation changes; no database or live backend writes are performed.

## Decisions / Deviations

- Account-scoped profiles replace the earlier user-level aggregation explicitly required by V0.11.
- Keep Next.js App Router and statically export existing routes; nginx handles production proxying and fallback, avoiding a framework migration.
- Public Demo is local-only; remove the legacy real-user gateway and migrate its tests.
- Existing user documents are preserved; historical V0.1 sources receive a supersession notice instead of destructive rewriting.
- Removed fixed-user gateway components and their obsolete tests. Replaced their coverage with session, string-ID, ownership, proxy and V0.11 workflow checks; quality scripts remain enabled.
- Added only the required shadcn Field/Label/NativeSelect primitives from the official registry. The existing Base UI foundation, Nova preset and dependency versions are preserved.

## Final audit evidence

- Runtime source has one centralized `fetch`, under `/api/v1`; no legacy user endpoints, numeric ID conversions, browser token storage or direct provider/database access remain.
- Queries include user, binding, resource and parameters. Account switches cancel reads and reset the mounted page; recursive DTO validation rejects nested mismatched account IDs. Logout removes private queries and pending reads; late mutations verify the initiating identity/binding.
- Coverage includes paginated account discovery, IDs above `Number.MAX_SAFE_INTEGER`, delayed account responses, unbinding and separate same-handle historical bindings, four analysis windows, immutable snapshots, recommendation retry keys, nullable/Gym/team/PENDING data, zero candidates, stale results, PARTIAL terminal jobs and rate-limit cooldowns.
- Desktop/mobile visual inspection retained the existing Nova presentation; automated layout checks include a 320 px viewport and 200% text size. The public Demo stays local and makes no learner API requests.
- Final checks passed: `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test` (40 tests), `pnpm build`, `pnpm test:e2e` (43 desktop/mobile tests), `git diff --check`, Node script syntax checks and merged Docker Compose configuration validation. The production build exports all 15 pages. The E2E proxy regression also verifies absolute-form request URLs cannot select another upstream.
- `pnpm test:container` did not pass: the first Docker build encountered a daemon layer-export EOF; a retry completed the container production build but could not pull `nginx:stable-alpine`. Docker Hub returned `connect: connection refused` for its registry HTTPS endpoint. The nginx runtime/browser acceptance remains unverified; rerun when registry connectivity is restored. No live backend mutation was performed.
- Existing user edits and untracked requirements/source documents remain preserved. No private env files, credentials, production data or generated test/build artifacts were added to source.

## Remaining integration work

Compatibility with an actual V0.11 backend, Session/Origin production configuration, mail delivery, Codeforces synchronization and Algorithm availability cannot be established by synthetic fixtures. Validate those services during deployment; the frontend does not emulate missing production capabilities.
