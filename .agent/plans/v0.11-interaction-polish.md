# V0.11 interaction detail polish

## Goal

Make existing screens respond clearly to hover, press, focus, selection, disclosure and refresh without changing their layout or visual identity.

## Context

The app already uses shadcn Base UI/Nova, Tailwind and tw-animate-css. Prefer the installed primitives and animation presets, preserve guest access and account isolation, and avoid another animation runtime or custom keyframes.

## Scope

### In Scope

- Consistent button/link/toggle press feedback, card hover/focus elevation and input hover/focus states.
- Existing library transitions for disclosures, tooltips and result entrance.
- Explicit current-page refresh with pending/success feedback and account-safe reads.
- Keyboard, touch, disabled states and reduced motion.

### Out of Scope

- Layout redesign, new backend endpoints, API/DTO changes, fake progress or pointer tracking effects.

## Acceptance Criteria

- [x] Existing controls have consistent and visible feedback without implying static content is clickable.
- [x] Disclosure and refresh interactions remain accessible and preserve focus/input state.
- [x] Manual refresh reads only the current user's active account/page queries and never shows late success after switching identity or route.
- [x] Reduced motion disables movement without removing status information.
- [x] Formatting, lint, TypeScript, unit tests, build and relevant browser regressions pass.

## Implementation Stages

1. Audit and update shared primitives using existing library presets.
2. Compose disclosure/tooltips and account-scoped refresh feedback.
3. Validate desktop/mobile, keyboard, reduced motion and request isolation.

## Testing

Use the isolated synthetic backend for refresh success/failure, slow/duplicate clicks, account-switch races, disclosure keyboard behavior and visual interaction checks. Run repository checks and browser regressions after the production build.

## Risks

Hover must not move form inputs or chart hit targets. Disabled actions must not react as enabled controls. Success feedback must reflect actual completed reads, and animation must not remount forms or retain old account results.

## Rollback / Reversibility

Changes are limited to shared presentation primitives and refresh UI; no backend migration or dependency changes are required.

## Progress

- [x] Inspect installed components and library docs.

- [x] Validate and review.

## Decisions / Deviations

- Use existing tw-animate-css presets and Base UI lifecycle attributes instead of introducing another animation runtime.
- Registry CLI documentation lookup failed with a closed connection; used official shadcn/Base UI documentation and the already-installed component sources. No registry component was overwritten.
- Enable ECharts' built-in 300 ms entrance / 200 ms update transitions, with a cleaned-up media query listener for reduced motion.
- Base UI 1.8 tooltips are supplementary visual labels, with accessible names on their triggers. Browser tests assert the visible popup and keyboard dismissal rather than assuming an obsolete tooltip role.
- Populated English practice content exposed long-label overflow at 320 px / 200% text size. Reuse the existing button/badge wrapping variants and measure loaded content in the accessibility regression.
- Full mobile regression exposed an existing session-resolution remount race: changing practice mode before `/me` completes could reset the selection. Keep the account context wrapper mounted, disable private reads until authentication, and reset its account preference state per user identity. The slow-account regression now explicitly holds both session and account responses to cover that transition.

## Validation Evidence

- TypeScript, ESLint, formatting, unit tests (50), production build and diff whitespace checks pass.
- Interaction/accessibility browser checks pass on desktop and mobile (12).
- Reviewed desktop refresh completion, login hover/focus/tooltips and mobile practice using the isolated fixture. Full desktop/mobile browser regression passes (81), including the deterministic session-resolution race regression.
- API/DTO contract and dependencies are unchanged by this polish. Refresh only performs active GET queries; no real-backend writes or deployment were performed.
