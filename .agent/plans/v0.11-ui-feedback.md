# V0.11 authentication and request feedback polish

## Goal

Make authentication visually polished and make backend-dependent UI feel responsive, with accessible loading animation and top-of-page notifications for slow or failed requests.

## Context

The V0.11 implementation already provides real session/captcha workflows and isolated account queries. Its login form is a compact default card, while shared feedback exposes raw errors inline. Keep the existing Next.js, Nova/Base UI, bilingual strings and API behavior. Preserve all in-progress V0.11 changes.

## Scope

### In Scope

- Responsive branded authentication layout, refined form composition, password visibility, captcha loading and button feedback.
- Base UI Toast, Spinner and InputGroup primitives within the existing design system.
- Shared query skeletons, background refresh indicators, delayed notifications, friendly failure recovery and optional diagnostic details.
- Reduced-motion support, desktop/mobile visual review and regression checks.

### Out of Scope

- Backend changes, authentication contract changes, new design systems or unrelated page redesigns.

## Acceptance Criteria

- [x] Login, registration and reset retain their existing contract and keyboard behavior.
- [x] Initial loading and background refresh have appropriate animations; slow reads notify once at the top.
- [x] Failed reads stop showing progress, allow retry and preserve successful data; raw details are disclosed on demand.
- [x] Account switches/unmounts clean up request notifications.
- [x] Mobile layouts, reduced motion, bilingual text and existing quality checks pass.

## Implementation Stages

1. Add missing Base UI primitives and redesign authentication composition.
2. Introduce shared request feedback and refine pending action buttons.
3. Verify request lifecycles and visually inspect desktop/mobile screens.

## Testing

Use the isolated V0.11 backend for delayed captcha, request failure/recovery, toast cleanup, password visibility, keyboard and mobile layout checks. Run formatting, lint, typecheck, unit tests, production build and desktop/mobile E2E.

## Risks

Avoid indefinite spinners on terminal failure, duplicate toasts from polling, stale notices after account switches, or disabling error recovery. Do not submit to the live backend during testing.

## Rollback / Reversibility

Changes are local to authentication, shared feedback, approved primitives and translations. Revert this UI work independently of the existing V0.11 contract implementation.

## Progress

- [x] Inspect current authentication and feedback.
- [x] Implement UI and state feedback.
- [x] Verify and review.

## Decisions / Deviations

Use a top-centered, nonblocking Base UI toast instead of a modal for slow requests so keyboard focus and form input remain intact. Show a notice after eight seconds; stop the loading presentation on failure and retain an explicit retry control. Diagnostic codes/request IDs remain available in a details disclosure.

## Verification and implementation notes

- Reused Nova Card, Button, Field, Empty, Alert and Skeleton; added the official Base UI InputGroup/Toast/Spinner primitives and InputGroup's Textarea dependency. The shadcn CLI failed with a registry connection error, so new component source was fetched from the official base-nova registry, inspected and adapted to Lucide/local imports. No package, preset or component-foundation change was needed.
- Authentication now uses a dedicated responsive shell, a CSS/SVG orbital illustration, comfortable input groups, password visibility, a compact captcha, a prominent submit action, and restrained entry/hover/loading animations. Registration and reset share the same presentation.
- Initial reads use skeletons and spinners; background reads retain existing content. Eight-second notices use top-centered Base UI Toast and clean up on completion/unmount/account switch. Terminal failures stop loading and expose an explicit retry. Captcha failures use the toast plus compact retry/diagnostic controls, not an inline error card.
- Error codes/request IDs are available through a disclosure. Sync stage failures keep readable stage/retry information with technical codes collapsed. Sync, binding, recommendation and security actions show submitting indicators.
- Reduced-motion preferences disable decorative animation and spinner rotation. E2E verifies keyboard focus, password visibility, failure recovery, notification position/deduplication/cleanup and native login validation. The captcha is required for login submission; the email-verification captcha does not block subsequent registration or email-change submission after it has been consumed.
- Typecheck, lint, formatting, 40 unit tests and the production build passed. The complete desktop/mobile E2E run passed 51 tests. After the final compact-captcha feedback adjustment, the production build and all 20 focused desktop/mobile authentication/accessibility regressions passed again.
- Visually reviewed desktop/mobile login, registration and slow-data states using the isolated synthetic backend. Also inspected the mobile captcha-unavailable state: the toast conveys the failure, while the form retains a compact retry and optional details. Review images are outside the repository in `/tmp/cst-ui-review/`; the displayed sample captcha is a review-only fixture.

## Remaining risks

Actual backend availability and authentication delivery remain deployment concerns. This UI work does not replace or invent backend data. Existing V0.11 implementation and user documents are preserved; no live backend writes were used for verification.
