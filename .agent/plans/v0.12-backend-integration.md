# V0.12 Backend Integration

## Goal

Implement the complete V0.12 student and coach flows against the two supplied specifications, preserving account-level V0.11 behavior and the existing static-export design system.

## Context

The authoritative contract is `prompts/V0.12-前端api文档.md`; its companion data-model document explains relationships. Existing implementation uses validated same-origin API requests, user/account-partitioned TanStack Query, Base UI/Nova, bilingual strings, static Next.js export and a local synthetic backend. User changes already remove historical documentation and plans; preserve them.

## Scope

### In Scope

- User aggregate analysis, frozen personal reports, separate AI jobs.
- Teams, applications, invitations, members, privacy-scoped member views.
- Team analysis/recommendations, coach navigation/dashboard, coach code redemption.
- Privacy and notifications, mutation invalidation and errors.
- Contract-valid synthetic backend, stories, unit/integration/E2E checks and integration documentation.

### Out of Scope

- Admin UI, backend/Algorithm implementation, algorithm calculation, deployment.
- Architecture/dependency upgrades or restoration of deleted documents.

## Acceptance Criteria

- [x] All new documented endpoints and DTOs use the existing API boundary.
- [x] Student dashboard/profile/reports no longer require selectedAccountId.
- [x] Role and team/member capabilities come from backend responses.
- [x] Cache includes identity, team, audience and all filters; logout clears it.

- [x] Old reports use frozen statistics/profile/recent snapshots.
- [x] Mock fixtures cover all specified states and preserve relationships.
- [x] Lint/format/types/unit/build/Storybook/E2E and browser inspection pass.

## Implementation Stages

### Stage 1 — Contract and state boundaries

Add validated DTOs/endpoints, query keys, polling/invalidation/error behavior. Verify runtime validation and scope isolation.

### Stage 2 — Student aggregate and reports

Replace dashboard/profile/personal analysis data sources. Retain account analysis in account details. Verify null/stale/zero and immutable history.

### Stage 3 — Collaboration

Add route-scoped teams and member views, coach management/dashboard, privacy and notifications. Verify transitions, capabilities, terminal states and audience isolation.

### Stage 4 — Fixtures and verification

Extend offline service and stories; add regression tests, run all requested checks and inspect rendered responsive pages. Update README/integration guide with actual behavior.

## Testing

- Unit: DTO validation, API paths/scoped responses, cache invalidation, job states, notification routes.
- Integration: synthetic endpoint state machines, permissions and mock consistency.
- E2E: aggregate independence, reports, teams/applications/invitations, coach management, privacy, notifications, job polling, isolation and errors.
- Build/type/lint: repository scripts including both Storybook build and browser suite.

## Risks

- API document leaves response payloads for leave/remove/read/read-all/redemption and unread-count unnamed. Consume unspecified mutation responses without inventing DTO fields; isolate unread-count decoding and document the integration assumption.
- Static export cannot generate unknown UUID paths at build time. Use exported fixed routes with UUID query parameters; API paths remain unchanged.
- Existing tests that assert account-based profile/dashboard semantics must be migrated to the explicitly newer contract, retaining account regression coverage.
- No live backend or Algorithm verification is possible through synthetic tests.

## Rollback / Reversibility

All edits are local and uncommitted. Revert only task-owned changes; preserve pre-existing user edits and deleted documents.

## Decisions / Deviations

- Preserve static export and use `/teams/detail?teamId=...` and `/teams/member?teamId=...&memberPublicId=...` for unknown IDs.
- P2 endpoints are included; no Admin UI is introduced.
- Native TypeScript imports are shared with the Node 24 offline backend; `allowImportingTsExtensions` is enabled with the existing noEmit/bundler settings. Compiler strictness remains enabled.
- `canManage` and membership changes partition automatic team-analysis reads; transfer immediately withdraws coach recommendation presentation.
- Account-list navigation now opens account data at `/data`; personal `/dashboard` remains aggregate-only.
- Unit checks cover visibility pause/resume, three-second polling, network backoff, terminal states, scoped invalidation, immutable report sources and resolvable rebuild results.
