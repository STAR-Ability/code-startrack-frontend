# V0.2 Frontend Delivery

## Goal

Deliver the complete codeStartrack V0.2 frontend training loop: authenticated
platform problem bank, safe problem statements, online code editing, idempotent
submissions, asynchronous judging, independent static analysis, training records,
four-window learning profiles, and mixed platform/Codeforces recommendations.
Keep authentication, CF account integration, coach/team workflows, privacy,
reports, notifications, bilingual copy, and the established design system working.
Publish verified development commits only to `dev`, maintain GitHub tracking, and
create a final `dev` to `main` PR after acceptance and CI pass. Do not merge or deploy.

## Context

- Current branch: `dev`; baseline: `dfeddc2`.
- Stack: Next 16.3.6 App Router static export, React 19, TypeScript strict,
  Tailwind v4, shadcn Base UI/Nova, TanStack Query, Zod, ECharts, Vitest/Playwright.
- Source specifications: all seven current documents in `prompts/`; V0.2 API,
  database reference, and architecture govern the additive V0.2 implementation.
- Browser requests remain same-origin `/api/v1/**`; nginx serves static exports
  on port 80. Resource IDs remain decimal strings or UUIDs as documented.
- Existing documentation renames and V0.2 additions were present before this
  task. Preserve their contents and include authoritative specifications in the
  delivery without rewriting them to suit the implementation.
- Existing `/profile`, `/practice`, and account/team/report clients retain their
  CF-specific responsibilities. The main dashboard gains combined learning data
  and links to explicit V0.2 workspaces.

## Scope

### In Scope

- Exact new public DTOs, runtime validation, API and admin calling signatures.
- Private, identity/version/filter-scoped caches; safe mutation ownership checks.
- Login-required problem browsing; STUDENT personal operations without CF binding.
- Query-parameter detail routes compatible with static export.
- Dynamic language intersection, immutable problem versions, safe Markdown,
  samples and provenance; ephemeral identity/version/language-scoped code drafts.
- Unmodified source, UTF-8 byte validation, uncertain-request idempotency recovery,
  version/language conflicts retaining source, independent judge/analysis states.
- 3-second polling, visibility pause/resume, network backoff, task/revision identity,
  30-second reconciliation for retryable locally failed judge dispatches.
- Submission list/detail/source, diagnostics/tool evidence/synthesis placeholder.
- Training plan/list/detail, source/status/date filters, actual-result completion.
- Learning latest/history/snapshot for all four windows and rebuild job handling.
- Recommendations with all sources/modes, explicit generation, history/detail,
  frozen rank/reasons, backend completion flags, and training attribution.
- Synthetic HTTP mocks, meaningful unit/E2E/Storybook coverage, responsive browser
  review, independent milestone review, existing feature regression and CI.
- Proxy request budget alignment, integration notes and README updates.
- GitHub milestone, prioritized dependent issues, incremental `dev` commits/pushes,
  and final unmerged PR with reproducible test evidence and limitations.

### Out of Scope

- Backend/judge/algorithm implementation, business database ownership or mutation.
- Complete administrator product UI (the contract explicitly permits API signatures).
- New LLM synthesis execution; V0.2 synthesis remains NOT_REQUESTED.
- Automatic merge, image publication, production deployment, or live backend writes.

## Risks

- V0.2 legacy tables omit the V0.12 team recommendation audience field while stating
  legacy semantics remain unchanged. Preserve established legacy features, document
  the contradiction, and verify any compatibility decision against executable backend
  evidence before changing old wire contracts. New V0.2 fields are strictly documented.
- No real V0.2 backend availability is yet proven; synthetic testing is not evidence
  for actual go-judge/tool/service callback integration or four-container resilience.
- Real ECharts setup is loaded before its test lifecycle; the ordinary complete
  unit script passed with the repository's two-worker configuration.
- Browser preview, E2E, Next build and dev servers share artifacts/ports and must
  have explicit ownership. Static export requires query-based unknown-ID detail pages.
- Private source/drafts and old team privacy boundaries require focused review.

development commits to remove V0.2 work without changing business data or history.
