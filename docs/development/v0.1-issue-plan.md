**Global network rule for every entry and every derived implementation prompt:** the live backend at `http://116.62.214.151:8080` is GET-only. Never issue POST, PUT, PATCH, DELETE, HEAD or OPTIONS probes to it. Never call mutation paths using GET. No bind, sync, reset, seed, repair, hidden setup writes, or production mock success. The gateway forwards only E1 for user 1 and E2 for user 1 with `limit=1`; optional manual documentation inspection is `GET /v3/api-docs`, which is not exposed through the gateway. This restriction applies to browser/server code, scripts and tests. Deferred scopes below are future specifications, not executable instructions under the current policy.

Use `DEMO_USER_ID = 1` from one replaceable configuration export and **server-only runtime** `BACKEND_BASE_URL`. Local/server configuration is `BACKEND_BASE_URL=http://116.62.214.151:8080`; `.env.local` and the Compose `.env` remain local-only, while `.env.example` contains a neutral `BACKEND_BASE_URL=`. Never expose the backend address through `NEXT_PUBLIC_*`, client imports, HTML/JS, configuration APIs or errors. This planning amendment changes only three documents; V01-01 migrates the existing local public-key configuration and relevant setup/contract wording.

The browser uses `GET /api/training/profile` and `GET /api/training/recommendation` on the Next.js origin. These frontend-owned technical routes map only to `GET /api/users/1/profile` and `GET /api/users/1/recommendations?limit=1`; they are not new backend APIs or product pages. The server fixes identity/query, rejects arbitrary proxy inputs, validates upstream responses and returns safe normalized errors. HEAD/OPTIONS and rejected methods make zero upstream calls. Ordinary navigation to the returned external problem URL remains allowed. No identity provisioning or authentication work is added.

For every future UI Issue, automatically apply the installed shadcn/ui Skill and configured shadcn MCP where relevant. Reuse existing Base UI/Nova components before custom primitives or new UI libraries. Preserve the two-page model and the existing form/query/test dependencies.
