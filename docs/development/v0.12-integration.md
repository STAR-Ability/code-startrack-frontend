# V0.12 frontend integration

## Authoritative contracts

Use `prompts/前端api文档.md` and `prompts/前端需要知道的数据库.md` for V0.11 authentication, sessions, bindings, synchronization, account-level data and recommendations. `prompts/V0.12-前端api文档.md` adds the V0.12 public contract and overrides personal dashboard/profile/report semantics; its data-model companion describes relationships without exposing database or Algorithm dependencies.

The browser requests only same-origin `/api/v1/**`, including credentials. The existing frontend proxy preserves the prefix and Origin; the production upstream remains `http://backend:8081`. No database, Algorithm, provider, LLM or internal credentials are needed in the frontend.

## Page boundaries

| Page                                                                         | Source                                                                                                 |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `/dashboard`                                                                 | User overview/analysis, latest report, joined teams, pending invitations, unread count                 |
| `/profile`                                                                   | User aggregate latest/history/snapshots; backend-owned source accounts                                 |
| `/analysis`                                                                  | Personal reports, frozen historical snapshots, current ALL/30D user analysis                           |
| `/accounts`, `/accounts/profile`, `/accounts/analysis`, `/data`, `/practice` | Existing account-scoped V0.11 endpoints                                                                |
| `/teams`                                                                     | Joined teams, applications, invitations and search                                                     |
| `/teams/detail?teamId=UUID`                                                  | Team header and URL-driven overview/members/analysis/recommendations/applications/invitations/settings |
| `/teams/member?teamId=UUID&memberPublicId=UUID&view=…`                       | Fresh team-specific dataAccess followed by one independently authorized data domain                    |
| `/privacy`                                                                   | Four independent backend privacy scopes                                                                |
| `/notifications`                                                             | Structured references, read state and unread count                                                     |
| `/coach`, `/coach/teams`, `/coach/teams/create`                              | Additive COACH role; specific management still requires TeamDetail.canManage                           |
| `/security/coach`                                                            | Coach invite-code redemption followed by /me refresh                                                   |

Unknown UUIDs use query parameters on fixed exported pages because the existing deployment is a static Next.js export. UUIDs still appear unchanged in API paths. Team task deep links add `&tab=members` (or another task). Management visibility uses fresh TeamDetail.canManage. `/coach/teams?task=applications` and `?task=invitations` are managed-team directories leading into that team’s queue, not invented global APIs. Account selection never changes a personal aggregate; it remains an account-page preference partitioned by publicId.

Reports render their own statistics, profile and recent-training snapshots. A report does not supply timezone; its Instant range is shown in UTC and supplied activity dates are preserved. Current user analysis is presented separately. Shared training and ability DTOs are never joined into a combined member view.

## Cache and tasks

All private keys start with `private, publicId`. Team keys additionally contain teamId, resource and every endpoint/filter/page; recommendation keys include audience. Queries consume AbortSignal, so abandoned observers cancel their reads. Team route changes remount detail state. 403/404 withdraw unavailable data; 5xx preserve successful cached results and allow retry. Logout clears private queries and mutations.

Mutations refresh the documented affected object families. Privacy updates never calculate team profiles locally. AI jobs have their own type and hook, poll every three seconds, stop at terminal states, pause when hidden and refresh when visible. Network failures back off up to thirty seconds. A task error retains prior report/history results.

## Contract gaps to confirm during backend integration

The supplied OpenAPI and deployed `/v3/api-docs` have identical paths and schema structure (after ignoring exporter-only `refType` metadata). Both still describe the API as v0.11 in `info`; use the actual paths rather than that label.

| Area               | Incremental prose / initial frontend                          | Current OpenAPI                                              | Resolution                                                                                                |
| ------------------ | ------------------------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| Unread count       | Response unspecified; initial adapter expected `unreadCount`  | `{data: {count: number}, requestId}`                         | Read `count`; validate it at the boundary.                                                                |
| Member submissions | Item unspecified; initial adapter expected bare SubmissionDto | Page of UserSubmissionDto (`sourceAccount`, `submission`)    | Validate both and display the supplied account source.                                                    |
| AI creation status | Prose specifies 202 for user analysis/report                  | OpenAPI lists 200 for all AI creation endpoints              | Accept HTTP success and validate AiJobDto; do not branch on one success status.                           |
| Team editing       | Nullable description/avatar in initial request                | PATCH description says empty string clears an optional field | Normalize clearing to empty string for PATCH; creation keeps its documented payload.                      |
| Transfer           | Prose only identifies new owner UUID                          | Active member must also have COACH                           | Explain this requirement; backend decides eligibility because TeamMemberDto does not expose system roles. |

Live verification on 2026-10-04 used an independent loopback SSH tunnel to `startrack-prod:8081`. The existing local 8081 listener was preserved; this check used local 18081. All 85 paths, 97 operations and schemas matched the supplied OpenAPI after ignoring exporter-only `refType` metadata. The exported description also retains legacy decimal-ID guidance; V0.12 team/user/job DTOs and paths use UUIDs. Neither the description nor the version label overrides the operation schemas.

With Mock disabled, seven unauthenticated reads returned HTTP 401 with `SESSION_EXPIRED`, an empty details object and requestId: `/me`, `/me/analysis/latest?window=ALL`, `/me/reports/latest`, `/me/privacy`, `/notifications/unread-count`, `/teams/mine?scope=JOINED` and `/coach/dashboard`. Responses had no Mock header. The real frontend proxy was inspected in a browser on desktop `/teams` and mobile `/coach`: both displayed the login gate, had no horizontal overflow or JavaScript/hydration errors, and requested only same-origin `/api/v1/me`. The expected HTTP 401 appears in the resource console.

Authenticated student, coach, owner and member integration flows are NOT RUN: no designated test session was supplied, and the user confirmed that a STUDENT+COACH account is currently unavailable. Mock workflow results do not establish those live behaviors. No production mutations, customer data access, new accounts or backend changes have been performed.

The final export was also inspected against the real backend on `/practice` at 320px with English and 200% text. The compact header measured 257px instead of the previous 525px, had no horizontal overflow, and the Sheet returned focus after Escape. Only the expected same-origin `/me` 401 was requested; no Mock or private account requests occurred.

## Offline verification

Use Node 24 and pnpm from package.json. Run `pnpm dev:mock`, or build then run `pnpm preview:mock`. The synthetic service is loopback-only and retains V0.11 behavior. `MOCK_SCENARIO=coach` enables STUDENT+COACH; additional scenarios include `no-sharing`, `no-report`, `ai-failed`, `mixed-privacy`, `empty`, `stale`, `no-accounts`, `not-generated`, `slow` and `error`. Synthetic mutation state is in memory and resets on restart. No live failure enables mock data.

Run `pnpm check`, `pnpm test:e2e`, `pnpm build-storybook` and `pnpm test:storybook`. E2E owns ports 3100/3210; stop preview before running it. Stories use production components and synthetic DTOs without network dependencies. Interactive collaboration stories reuse the local service state machine through a Storybook-only request interceptor. See [the scenario matrix](v0.12-mock-scenarios.md) for identity presets, recovery states and switching instructions. These checks verify the public contract and frontend behavior against a mock, not real service compatibility, email delivery or Algorithm/LLM execution. Container checks require Docker.
