# V0.12 frontend integration

## Authoritative contracts

Use `prompts/前端api文档.md` and `prompts/前端需要知道的数据库.md` for V0.11 authentication, sessions, bindings, synchronization, account-level data and recommendations. `prompts/V0.12-前端api文档.md` adds the V0.12 public contract and overrides personal dashboard/profile/report semantics; its data-model companion describes relationships without exposing database or Algorithm dependencies.

The browser requests only same-origin `/api/v1/**`, including credentials. The existing frontend proxy preserves the prefix and Origin; the production upstream remains `http://backend:8081`. No database, Algorithm, provider, LLM or internal credentials are needed in the frontend.

## Page boundaries

| Page                                                                         | Source                                                                                 |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `/dashboard`                                                                 | User overview/analysis, latest report, joined teams, pending invitations, unread count |
| `/profile`                                                                   | User aggregate latest/history/snapshots; backend-owned source accounts                 |
| `/analysis`                                                                  | Personal reports, frozen historical snapshots, current ALL/30D user analysis           |
| `/accounts`, `/accounts/profile`, `/accounts/analysis`, `/data`, `/practice` | Existing account-scoped V0.11 endpoints                                                |
| `/teams`                                                                     | Joined teams, applications, invitations and search                                     |
| `/teams/detail?teamId=UUID`                                                  | Team capabilities, members, analysis/recommendations, authorized management            |
| `/teams/member?teamId=UUID&memberPublicId=UUID&view=…`                       | Fresh team-specific dataAccess followed by one independently authorized data domain    |
| `/privacy`                                                                   | Four independent backend privacy scopes                                                |
| `/notifications`                                                             | Structured references, read state and unread count                                     |
| `/coach`, `/coach/teams`, `/coach/teams/create`                              | Additive COACH role; specific management still requires TeamDetail.canManage           |
| `/security/coach`                                                            | Coach invite-code redemption followed by /me refresh                                   |

Unknown UUIDs use query parameters on fixed exported pages because the existing deployment is a static Next.js export. UUIDs still appear unchanged in API paths. Account selection never changes a personal aggregate; it remains an account-page preference partitioned by publicId.

Reports render their own statistics, profile and recent-training snapshots. A report does not supply timezone; its Instant range is shown in UTC and supplied activity dates are preserved. Current user analysis is presented separately. Shared training and ability DTOs are never joined into a combined member view.

## Cache and tasks

All private keys start with `private, publicId`. Team keys additionally contain teamId, resource and every endpoint/filter/page; recommendation keys include audience. Queries consume AbortSignal, so abandoned observers cancel their reads. Team route changes remount detail state. 403/404 withdraw unavailable data; 5xx preserve successful cached results and allow retry. Logout clears private queries and mutations.

Mutations refresh the documented affected object families. Privacy updates never calculate team profiles locally. AI jobs have their own type and hook, poll every three seconds, stop at terminal states, pause when hidden and refresh when visible. Network failures back off up to thirty seconds. A task error retains prior report/history results.

## Contract gaps to confirm during backend integration

The supplied incremental document does not name the JSON response for unread count. The isolated adapter currently expects `ApiResponse<{unreadCount: number}>`; confirm this field with the backend before asserting live compatibility. Leave/remove/read/read-all/redemption responses are deliberately consumed without assuming a success DTO or status beyond HTTP success. Team recommendation generation follows the documented AI job lifecycle with `AiJobDto.type=TEAM_RECOMMENDATION`; confirm the undocumented generation response/status at integration time. No alternative endpoint or algorithm calculation is introduced.

## Offline verification

Use Node 24 and pnpm from package.json. Run `pnpm dev:mock`, or build then run `pnpm preview:mock`. The synthetic service is loopback-only and retains V0.11 behavior. `MOCK_SCENARIO=coach` enables STUDENT+COACH; additional scenarios include `no-sharing`, `no-report`, `ai-failed`, `mixed-privacy`, `empty`, `stale`, `no-accounts`, `not-generated`, `slow` and `error`. Synthetic mutation state is in memory and resets on restart. No live failure enables mock data.

Run `pnpm check`, `pnpm test:e2e`, `pnpm build-storybook` and `pnpm test:storybook`. E2E owns ports 3100/3210; stop preview before running it. Stories use production presentations and synthetic DTOs without network dependencies. These checks verify the public contract and frontend behavior against a mock, not real service compatibility, email delivery or Algorithm/LLM execution. Container checks require Docker.
