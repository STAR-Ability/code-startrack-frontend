# V0.12 workspace delivery

## Product and architecture changes

The existing API client, session providers, TanStack Query layer, static-export routes and design tokens were retained. CodeGraph MCP traced dependencies before refactoring. The supplied API/data documents and OpenAPI were reviewed in full. No backend APIs, database schema, Algorithm integration or deployment were changed.

The sidebar now groups learning, collaboration, coach workspace, accounts/data and settings. Groups collapse, active links reflect URL task state, desktop icon mode retains tooltips and its layout cookie, and mobile navigation uses a focus-trapped Sheet. COACH adds a visible workspace below common capabilities; it does not replace STUDENT or confer management access to every team.

Team names and an explicit Open team action provide primary navigation. Secondary tasks use a contextual menu. Team detail separates overview, members, analysis, recommendations, applications, invitations and settings. Header identity, status, owner, current membership and active member count stay visible. Overview links pending application/invitation counts and analysis/data readiness into the relevant task. Management sections use TeamDetail.canManage, leaving uses canLeave, and member data entry points use dataAccess. Backend errors remain authoritative.

Coach dashboard gives managed-team and pending-work actions prominence. Managed team directories lead into team-specific application/invitation queues. Privacy scopes use accessible Select fields. Notifications use compact activity rows and structured references. Shared surfaces distinguish metrics, headers, rows, charts, empty states and danger zones, with restrained orbit/grid decoration and reduced-motion support. Archive, dissolution, transfer, removal and leaving require deliberate confirmation; dissolution requires the exact team name.

## Routes and reusable components

Changed routes: `/teams`, `/teams/detail?teamId=UUID&tab=…`, `/coach`, `/coach/teams?task=…`, `/privacy` and `/notifications`, plus the shared workspace shell on existing routes. Team detail supports direct refresh/deep links. The static-export architecture uses the route query for UUIDs; no global selectedTeamId was introduced. Existing student dashboard/profile/reports remain aggregated `/me/**`; selectedAccountId remains account scoped.

Changed components: WorkspaceShell/Sidebar, compact mobile Brand, TeamsPage, TeamCard/team record rows, TeamDetailPage/TeamOverview, TeamMembers/TeamApplications/TeamInvitations/TeamSettings, TeamInsights/TeamRecommendations, CoachPage, PrivacyPage and NotificationsPage. The mobile header keeps navigation and language controls; the duplicate security link remains accessible through the sidebar. Added Base UI/Nova shadcn Select, Avatar, AlertDialog and DropdownMenu, plus ChoiceSelect composition and tested navigation helpers. Existing feedback, panels, metrics, status, chart, query and mutation helpers were reused. Chinese/English localization remains shared.

## Mock and Storybook

The existing loopback HTTP mock was extended rather than replaced. Typed builders reuse the actual DTO/schema definitions. Eight identities and 85 named presets cover account counts; additive coach/team roles; active/archived/dissolved teams; active/left/removed membership; every application/invitation/delivery status; registered and email-only invitees; privacy combinations; absent/fresh/stale/insufficient analyses; frozen reports and failed/pending jobs; both team audiences; empty recommendations; all four AI types and four job states; eight notification types; and 401/403/409/429/network/5xx errors with Retry-After.

Relationship invariants are tested: owners of active/archived teams are active members, canonical team references agree, analysis sample counts remain consistent, member fixtures cannot retrieve coach batches, and TeamSummary responses exclude TeamDetail permission fields. Collaboration identifiers/timestamps are deterministic. Mutations update in-memory business state; notification content is never used as that state.

Storybook adds 22 interactive collaboration stories and retains existing V0.12 presentations. A Storybook-only fetch interceptor uses the same HTTP state machine and request validation. Vitest and Playwright reuse the same fixture/scenario boundary. Production presentation components contain no scenario switches. See [the scenario matrix](v0.12-mock-scenarios.md) for presets and commands.

## Contract discrepancies and limitations

The initial frontend count adapter expected unreadCount; OpenAPI specifies count. Member submissions were initially treated as bare SubmissionDto; OpenAPI specifies sourceAccount plus submission. Both were corrected. PATCH clears optional team fields with the documented empty string. AI creation prose lists 202 whereas OpenAPI lists 200; the client accepts HTTP success and validates the DTO. Ownership transfer requires an active COACH member, but the member DTO does not expose system roles; the UI explains eligibility and lets the backend decide. Deployed API info still says v0.11 and contains legacy decimal-ID guidance despite the V0.12 operation schemas. Details are in [integration notes](v0.12-integration.md).

Remaining acceptance gap: authenticated real student/coach/owner/member flows, delivery and Algorithm/LLM execution require a designated test session/backend capability. Mock passing does not verify those services. Existing finished NativeSelect controls on account/data pages were retained to preserve established workflows. Static team UUID query routes remain intentional; no deployment migration was authorized.
