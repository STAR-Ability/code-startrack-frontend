## Version metadata and structural validation

All analysis/recommendation `algorithmVersion` fields and personal-report
`reportVersion` use the shared nonempty string schema. No single version literal
can reject an otherwise usable payload. `classifyAlgorithmVersion` identifies
exact audited versions separately from Zod parsing. A new version such as
`user-profile-v0.13.2` remains structurally valid and is classified `unknown` until
audited; the classifier must not be used to discard data.

Unknown versions show a nonblocking compatibility note with the exact supplied
version behind a details disclosure. Known versions add no notice. Shared member
ability DTOs and frozen report analysis snapshots omit Algorithm metadata in the
public contract; the frontend does not invent versions for them. Personal reports
show their own supplied `reportVersion` notice when needed.

Structural validation continues to enforce required fields, nullable values,
finite score ranges, six dimensions, protocol enums, opaque identifiers and
response identity checks. Invalid payloads raise `INVALID_RESPONSE`; absent
analysis remains the backend's explicit `null`. Account responses also preserve
`ACCOUNT_MISMATCH` checks. User rating-source `lastSyncedAt` remains required:
Backend `inspectSources` prevents new aggregate generation before every source
has completed a successful sync.

User/account/team profiles, shared ability profiles and frozen report profiles
check dimension identity/rank uniqueness and consistency with `weakestDimension`.
These invariants match Backend `AnalysisResultValidator` and
`TeamAnalysisService.validateDimensions`. A malformed HTTP-success response shows
a specific data-format error and retry action, rather than network guidance or a
not-generated empty state.

## Verification boundary

Read-only `/me`, `/me/analysis/latest?window=ALL` and other protected unauthenticated
reads returned HTTP 401 with `SESSION_EXPIRED`, an empty details object and a
request UUID. No production account, database session or mutation was accessed.
There is no designated authenticated test session. Authenticated student/coach,
analysis/recommendation and role checks must use the deterministic mock service;
they do not establish live authenticated behavior.

Regression coverage in `src/lib/api/algorithm-compatibility.test.ts` validates
V0.13.1, V0.13.2 and future version payloads, exact-family classification,
malformed data rejection and identity checks through the API adapters.
The default deterministic account/user fixtures use the deployed Algorithm
versions while retaining synthetic data and explicit mock transport provenance.
