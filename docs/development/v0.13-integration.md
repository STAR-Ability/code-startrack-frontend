## Version metadata and structural validation

All analysis/recommendation `algorithmVersion` fields and personal-report
`reportVersion` use the shared nonempty string schema. No single version literal
can reject an otherwise usable payload. `classifyAlgorithmVersion` identifies
exact audited versions separately from Zod parsing. A new version such as
`user-profile-v0.13.2` remains structurally valid and is classified `unknown` until
audited; the classifier must not be used to discard data.

Unknown versions show a nonblocking compatibility note with the exact supplied
version behind a details disclosure. Known versions add no notice. Shared member
ability DTOs and frozen report analysis snapshots omit Algorithm metadata in the
public contract; the frontend does not invent versions for them. Personal reports
show their own supplied `reportVersion` notice when needed.

Structural validation continues to enforce required fields, nullable values,
finite score ranges, six dimensions, protocol enums, opaque identifiers and
response identity checks. Invalid payloads raise `INVALID_RESPONSE`; absent
analysis remains the backend's explicit `null`. Account responses also preserve
`ACCOUNT_MISMATCH` checks. User rating-source `lastSyncedAt` remains required:
Backend `inspectSources` prevents new aggregate generation before every source
has completed a successful sync.

User/account/team profiles, shared ability profiles and frozen report profiles
check dimension identity/rank uniqueness and consistency with `weakestDimension`.
These invariants match Backend `AnalysisResultValidator` and
`TeamAnalysisService.validateDimensions`. A malformed HTTP-success response shows
a specific data-format error and retry action, rather than network guidance or a
not-generated empty state.

## Verification boundary

The initial unauthenticated audit returned HTTP 401 `SESSION_EXPIRED` from
`/me`, `/me/analysis/latest?window=ALL` and other protected reads. On 2026-10-06,
the current task separately authorized a designated administrator account for
login/session and read-only production acceptance. Real UI login succeeded, and
57 authenticated GET responses across 21 DTO families were inspected. All 53
successful responses passed current Zod validation; four expected
`TEAM_FORBIDDEN` envelopes were limited to management/COACH scopes of a team
whose membership was `MEMBER` with `canManage=false`. Global ADMIN/COACH roles
do not override that per-team ownership boundary. Thirty-nine captured responses
also passed the actual API adapters and their identity/account/window/audience
checks. No private payloads, account credentials or sessions belong in this
repository or public release receipts.

User/account profiles in all four windows, current/history reports,
recommendations, team/shared-member data, accounts, privacy, notifications and
coach reads were covered. Cached account snapshots legitimately used
`profile-v0.11.1` while current aggregate snapshots used
`user-profile-v0.13.1`; independently versioned families must remain usable.
Null LEVEL recommendations and absent team analysis were explicit backend empty
states. No generation, synchronization, settings or membership write was executed
against production. Those transitions use the deterministic synthetic service.

The production profile's six display-order scores were compared with textual
values and all six actual SVG data vertices, with less than 0.1px coordinate
error. Locale changes and widths 1440/1280/820/390/320 retained the polygon and
visible labels without overflow or page errors. Empty grid paths alone do not
prove rendered scores. The API-driven browser regression additionally uses
distinct synthetic windows, reversed response order, delayed delivery, locale,
viewport and reload transitions, and a grid-only rejection check. Final
post-deployment and session/logout acceptance is tracked in Issue #29 below.

Regression coverage in `src/lib/api/algorithm-compatibility.test.ts` validates
V0.13.1, V0.13.2 and future version payloads, exact-family classification,
malformed data rejection and identity checks through the API adapters.
The default deterministic account/user fixtures use the deployed Algorithm
versions while retaining synthetic data and explicit mock transport provenance.

## Analytical presentation and state reliability

Profiles distinguish latest and historical evidence, put ability structure ahead
of optional supporting distributions, and preserve exact numeric values outside
chart hover. Recommendations preserve supplied rank and ability coverage, including
null external links and completion states. Coach/account history failed reads do
not become zero counts or successful empty states. Shared Select labels and
translated controls reflow on narrow screens without altering selection semantics.

Chart instances survive option, locale, palette and theme updates. ECharts 6.1
retains old coordinates/media rules during merging and restores initial options
on setTheme; the adapter explicitly replaces obsolete coordinates/media and reapplies
latest options plus the current reduced-motion preference after theme changes.
Actual ECharts regressions cover refreshed data, accessible labels and responsive
geometry. Modern CSS colors are resolved through the browser before ECharts parses
them; team participation uses teal, while pending submissions use amber.
