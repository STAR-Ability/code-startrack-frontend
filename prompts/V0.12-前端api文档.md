# CodeStartrack / 码练星轨 V0.12 前端 API 增量契约

> 本文给 Frontend 开发者使用，只描述 V0.12 新增功能。V0.11 已实现的注册/登录、Session、多个 Codeforces 账号、同步、账号级数据/画像/推荐接口全部继续可用。
>
> V0.12 前端仍然只请求同源 `/api/v1/**`，由前端服务反向代理至 `http://backend:8081`。前端**不连接 PostgreSQL、不调用 Algorithm、不调用 Codeforces**。

## 1. V0.12 前端最重要的语义变化

V0.11：学生主页/画像主要围绕一个 `selectedAccountId`。

V0.12：

- **平台账号管理页**仍按 accountId 管理和查看单账号详情。
- **学生主页 / 个人画像 / 个人分析报告**默认改为“系统用户级多 CF 汇总”，调用 `/me/**` 新接口，不再要求 selectedAccountId。
- 用户拥有 `COACH` 时仍保留 STUDENT 功能，同时显示教练导航。
- Team/Privacy/Notification 是 Backend 业务数据；前端不根据数据库结构自行推断权限。

## 2. 继续沿用的 V0.11 协议

- Session Cookie `cst_session`，fetch 使用 `credentials: "include"`。
- JSON camelCase。
- `ApiResponse<T>` / `PageResponse<T>` / `ApiError`。
- bigint ID 是十进制 string；不能 `Number(accountId)`。
- UUID 作为 string。
- Instant 是带时区 ISO8601 UTC。
- null 与 [] 语义保持不变。
- 401 → 登录；403/409/429 按 `error.code`；5xx 保留已有数据并允许重试。

## 4. 应用初始化与角色导航

登录后仍先：

```text
GET /api/v1/me
```

前端只根据 `user.roles` 展示入口：

```text
roles 包含 STUDENT
→ 学生主页 / 画像 / 分析 / 推荐 / 团队 / 平台账号 / 设置 / 通知

roles 同时包含 COACH
→ 上述学生功能全部保留
→ 额外显示 教练主页 / 管理团队
```

不要使用 `primaryRole` 隐藏 STUDENT 功能；COACH 是额外角色，不是切换掉 STUDENT。

P2 教练邀请码兑换：

```text
POST /coach-invite-codes/redeem  {code}
→ 成功后刷新 GET /me
```

V0.12 不要求前端制作复杂 Admin 后台；管理员创建/禁用邀请码与人工授予 COACH 可先由内部管理工具调用后端 Admin API。

## 5. 用户级多 CF 画像接口

V0.12 学生主页、个人画像、个人分析不再依赖 selectedAccountId：

| 方法与路径 | Query | 响应 |
|---|---|---|
| GET `/me/training/overview` | window=30D | UserAnalysisDto 或 null |
| GET `/me/analysis/latest` | window=ALL | UserAnalysisDto 或 null |
| GET `/me/analysis/history` | window=ALL + 分页 | Page<UserAnalysisDto> |
| GET `/me/analysis/{snapshotId}` | 无 | UserAnalysisDto |
| POST `/me/analysis/rebuild` | 无 | 202 AiJobDto |

### 展示规则

- `currentRating` 文案写“最高当前 Rating”，因为它是绑定账号中的最大值。
- `ratingAccounts[]` 展示每个 CF handle 的独立 current/max Rating。
- `sourceAccountIds` 只用于诊断/缓存，不作为 UI 主文案。
- `stale=true`：可以展示旧画像，但要提示“数据已更新，画像正在重建/建议重建”。
- `analysis=null`：尚未生成用户级画像；如果有账号则显示“正在汇总/重建”，无账号则显示绑定引导。

## 7. 个人分析报告接口

| 方法与路径 | 响应 |
|---|---|
| GET `/me/reports/latest` | PersonalReportDto 或 null |
| GET `/me/reports` | Page<PersonalReportDto> |
| GET `/me/reports/{reportId}` | PersonalReportDto |
| POST `/me/reports/generate` | 202 AiJobDto；P2 手动重新生成 |

页面：

- 顶部当前报告。
- 中部统计/六维可使用报告冻结 `statisticsSnapshot/profileSnapshot`，确保历史回看与生成时一致。
- 历史列表按 generatedAt DESC。

- 手动生成遇到 429 使用 Retry-After 倒计时。

## 8. AI Job 轮询

```text
GET /ai-jobs/{jobId}
```

前端统一 hook：

```ts
useAiJob(jobId)
```

规则与 V0.11 sync job 一致：

- 202 后每 3 秒轮询。
- QUEUED/RUNNING：显示处理中。
- SUCCESS：根据 type 刷新对应 latest/history。
- FAILED：显示 errors，不丢已有历史结果。
- 页面不可见可暂停，恢复立即查一次。
- 网络错误指数退避，不重复创建 job。

## 9. 团队基础接口

| 方法与路径 | Request / Query | 响应 |
|---|---|---|
| POST `/teams` | `{name,description,avatarUrl}` | TeamDetailDto |
| GET `/teams/mine` | scope=ALL/JOINED/MANAGED + 分页 | Page<TeamSummaryDto> |
| GET `/teams/search` | q + 分页 | Page<TeamSummaryDto> |
| GET `/teams/{teamId}` | 无 | TeamDetailDto |
| PATCH `/teams/{teamId}` | name?/description?/avatarUrl? | TeamDetailDto |
| POST `/teams/{teamId}/archive` | 无 | TeamDetailDto |
| POST `/teams/{teamId}/activate` | 无 | TeamDetailDto |
| POST `/teams/{teamId}/dissolve` | `{confirmation: teamName}` P2 | TeamDetailDto |
| POST `/teams/{teamId}/transfer` | `{newOwnerPublicId}` P2 | TeamDetailDto |

固定列表语义：`scope=JOINED`/`MANAGED` 都只表示当前有效关系，不返回已经 LEFT/REMOVED 或 DISSOLVED 的历史团队；`/teams/search` 只返回 ACTIVE 可加入团队。已经是成员的 ACTIVE 团队可以出现在搜索中，但根据 `myMembershipRole` 显示“已加入”并隐藏申请按钮。

前端不要通过 roles 自己判断 owner 权限；使用 `TeamDetailDto.canManage/canLeave/myMembershipRole` 控制按钮，并接受后端最终 403/409。

## 15. 查看成员训练数据

| API | 对应 dataAccess |
|---|---|
| GET `/teams/{teamId}/members/{memberPublicId}/training/overview` → SharedTrainingOverviewDto | basicTraining |
| GET `/teams/{teamId}/members/{memberPublicId}/profile` → SharedAbilityProfileDto | abilityProfile |
| GET `/teams/{teamId}/members/{memberPublicId}/submissions` | detailedSubmissions |
| GET `/teams/{teamId}/members/{memberPublicId}/reports` | analysisReport |
| GET `/teams/{teamId}/members/{memberPublicId}/reports/{reportId}` | analysisReport |

- `dataAccess=false`：UI 默认不展示入口。
- `SharedTrainingOverviewDto` 与 `SharedAbilityProfileDto` 是故意拆开的最小响应；前端不得假定某个接口“应该还有”另一个权限域的数据，也不得用本地缓存拼成越权视图。
- 仍收到 403 `PRIVACY_DENIED`：提示“成员未向你开放此数据”，不要当系统错误。
- 404：刷新 team/member 数据，不泄漏其他团队资源。

## 16. 团队能力概览

```text
GET /teams/{teamId}/analysis/latest
GET /teams/{teamId}/analysis/history
POST /teams/{teamId}/analysis/rebuild   // OWNER/P2 或调试入口
```

前端不传 audience。Backend 根据当前身份返回：

- OWNER/COACH → COACH 版。
- 普通 member → MEMBER 版。

展示必须包含：

- includedMemberCount / memberCount（能力画像样本量）。
- trainingMemberCount（基础训练/近期活动样本量）。
- levelMemberCount（能用于计算团队目标难度的样本量）。
- excludedMemberCount。
- 六维平均能力。
- weakestDimension。
- 近期团队 activity。
- 数据不足提示。

`includedMemberCount=0` 时不要画误导雷达满 0 当真实水平，应标“当前没有成员允许共享能力画像”；`trainingMemberCount=0` 时趋势区域标“当前没有成员开放基础训练数据”；`levelMemberCount=0` 时团队推荐入口显示“缺少可用训练等级数据”。

## 17. 团队推荐（P2）

```text
POST /teams/{teamId}/recommendations/generate
GET  /teams/{teamId}/recommendations/latest
GET  /teams/{teamId}/recommendations/history
GET  /teams/{teamId}/recommendations/{batchId}
```

Owner 才显示“生成/重新生成”。生成时必须明确选择 audience：

- `MEMBER`：团队成员可见推荐；只允许使用 MEMBER audience 团队画像，以及 `detailedSubmissions=TEAM_MEMBER/PUBLIC` 且数据就绪的 coverage 成员。
- `COACH`：教练私有推荐；可以使用 COACH audience 团队画像，以及 OWNER 对应可见范围的 detailedSubmissions；**仅 OWNER 可读**。

调用约定：

```text
POST /teams/{teamId}/recommendations/generate
body: {audience: "MEMBER"|"COACH", mode?, limit?}

GET /teams/{teamId}/recommendations/latest?audience=MEMBER|COACH&mode=HYBRID
GET /teams/{teamId}/recommendations/history?audience=MEMBER|COACH&mode=...
```

普通成员只能获得 `MEMBER` 批次；OWNER 默认可看 `COACH`，也可切换查看 `MEMBER`。`TeamRecommendationBatchDto.audience` 必须参与 cache key，前端绝不能把 COACH 批次展示给普通成员。

团队推荐只返回团队级题目、分数和 Backend 固定 `reason` 文案，不返回逐成员或“完成成员数”字段；前端不得根据 reasonCode 自己重算排序/覆盖率。覆盖率仅在 Backend→Algorithm 内部计算。`candidateCount` 仅表示服务端完成全部内部资格过滤后、limit 截断前的候选量，用于“候选不足”提示，不等于题库原始候选数。

## 28. Loading / Empty / Error 状态

### Team

- mine=[] → “尚未加入团队”。
- search=[] → “未找到匹配团队”。
- pending applications=[] → 无待处理。
- invitations=[] → 无邀请。
- members=[] 理论上 ACTIVE 团队至少 OWNER；若返回空视为数据异常并显示 requestId。

### User Analysis

- null + 有有效 CF → “画像尚未生成/正在汇总”。
- null + 无 CF → 绑定引导。
- stale → 展示旧数据 + stale badge。

### Report

- null → “尚无分析报告”。
- FAILED job → 旧报告仍可继续看。

### Team Analysis

- null → “尚无团队分析”。
- includedMemberCount=0 → 隐私/数据不足提示，不当系统失败。
