# CodeStartrack / 码练星轨 V0.11 前端数据模型

## 服务与部署边界

```text
Browser → Frontend Service（frontend:80）→ Backend Service（backend:8081）
                                              ├→ PostgreSQL（postgres:5432）
                                              └→ Algorithm Service（algorithm:8000）
```

Frontend、Backend、Algorithm 各有独立代码、Dockerfile、依赖锁文件、构建命令和启动命令，可以独立构建、启动、部署。PostgreSQL 是基础设施。Frontend 负责页面、组件、交互、状态、API DTO 和 Mock；浏览器同源请求 `/api/v1/**`，由 frontend 反向代理到 `http://backend:8081`。Backend 是业务数据库唯一读写入口，负责认证权限、Codeforces Provider、标准化、同步和结果校验落库。Algorithm 是无状态独立 HTTP 服务，只接收后端 DTO，返回统计、六维画像和推荐。

Frontend 不连接数据库、不调用 Algorithm 或 Codeforces；Algorithm 不连接数据库、不调用 Codeforces，不接收密码、Session、Cookie，不依赖前端框架或后端 ORM。浏览器点击后端提供的原题链接属于页面导航，不是调用 Codeforces 数据 API。容器间地址使用服务名，不使用 localhost 或 127.0.0.1。

## 唯一数据契约

前端按 [前端 API 文档](前端api文档.md) 的 TypeScript DTO、端点表和空值语义开发。数据库表名、字段名、ORM、索引、算法函数都不是前端依赖。数据库 snake_case 到 API camelCase 的转换完全由 Backend 完成。前端负责 API Client、Mock、页面和状态管理，不建立数据库连接，也不根据表结构生成业务判断。

## 数据关系与稳定 ID

```text
一个系统用户
  ├─ CF 绑定 accountId A → 提交/做题/同步/四窗口画像/推荐历史 A
  └─ CF 绑定 accountId B → 提交/做题/同步/四窗口画像/推荐历史 B
```

一个用户可同时有多个 CF；一个有效 CF handle 只能属于一个用户。所有训练数据按绑定 accountId 隔离，不存在系统用户级合并画像。账号切换不改变登录用户，但切换全部数据查询上下文。

| 字段                                | JSON 类型     | 语义                             |
| ----------------------------------- | ------------- | -------------------------------- |
| publicId                            | UUID string   | 当前登录用户公开 ID              |
| accountId                           | 十进制 string | 一次 CF 绑定的稳定 ID，非 handle |
| problemId                           | 十进制 string | 全系统共享题目 ID                |
| submissionId / externalSubmissionId | 十进制 string | 系统提交 ID / CF 原始提交 ID     |
| jobId                               | UUID string   | 同步或重建分析任务               |
| snapshotId / analysisSnapshotId     | UUID string   | 画像 ID / 推荐所用同一画像的引用 |
| batchId                             | UUID string   | 一次成功推荐结果                 |

ID 作为不透明值传递，不 Number() 转换、不从 handle 推导、不做算术。分析快照和推荐批次包含 accountId；推荐还包含 analysisSnapshotId，可定位当时画像。集合类型 tagStats、difficultyStats、activityStats、dimensions、recommendations 始终为数组，不是 Map；具体字段以同目录前端 API 完整定义为准。

## 绑定生命周期

ACTIVE 正常绑定；INVALID 为暂时无法解析 CF 身份的有效占位，可重试同步或解绑；UNBOUND 已解绑，只读历史。网络超时不会自动使账号 INVALID。

解绑结束本次 accountId，但保留原用户历史；重新绑定同 handle 总是创建新 accountId，原用户也一样。已释放 handle 可以被其他用户绑定，对方只获得新绑定下重新同步的公开 CF 数据，不获得旧用户的画像、推荐或任务。旧历史可通过 includeUnbound=true 读取自己的记录。前端不能按 handle 合并新旧账号。

## 展示语义

- attemptedProblemCount 为尝试题数，solvedCount 为窗口内 AC 去重题数，unsolvedProblemCount 为窗口内未 AC 题数；submissionCount 是次数，不是题数。
- acceptedSubmissionCount、failedSubmissionCount、pendingSubmissionCount 三者之和为 submissionCount；PENDING 显示“等待判题”。
- difficulty 与 CF rating 可能缺失；null 显示“未评级/暂无”，不能填 0。题目 points 不是难度，memoryBytes 单位为字节。
- overallScore/六维 score 为 0..100，推荐 score 为 0..1；前端不自行计算或重排，维度顺序按 displayOrder，弱项按 weakestDimension 对应 code。
- tagStats 多标签可重复覆盖一题，不能求和当总题数。difficultyStats 的 null 桶是未评级题；activityStats 缺日期仅表示该日没有提交，图表补零。
- solvedCount 出现在 ProblemDto 时是 CF 公开通过人数，出现在 summary 时是当前 accountId 的窗口 AC 题数。没有 Codeforces 全站通过率字段。
- 分析或推荐不存在返回 null；成功分析但无训练是完整零画像；成功推荐无候选是 recommendations=[]。
- 同步数据与分析独立完成。PARTIAL/ANALYSIS 表示 CF 数据已保留、画像尚未成功更新；旧画像可以显示并标 stale。GET 不触发计算。

## 页面状态隔离

应用先读取用户和账号列表，选出 selectedAccountId 后才请求账号页面。缓存键至少含 publicId/accountId/window/mode；切换账号清理正在展示的数据并取消或忽略旧请求。解绑/退出清理相应缓存，绝不把一个 CF 的统计当成另一个 CF。没有有效账号显示绑定引导。具体页面请求顺序、loading/empty/error/syncing、分页与 Mock 均在前端 API 文档中定义。
